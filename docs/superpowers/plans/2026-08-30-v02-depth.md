# v0.2 Depth Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Wire `KarmicStore` and `Citta` into `Being`: conditional delayed karma, incarnation windows, an observable+generative vīthi (`cognize`), rebirth, serialization — per the approved spec.

**Architecture:** Additive integration. `Being` gains a `karmicStore` (timers off), incarnation tracking, `cognize()`, `rebirth()`, `dispose()`. `act()` dual-writes (legacy `karmicStream` + a seed). `receiveKarmicResults(force?)` keeps the legacy path and adds the conditional store path with `whyNot` explanations. `Citta` is never serialized (derived state, re-synced from `Mind` per cognize). All new `BeingData` fields optional (legacy saves load with defaults).

**Tech Stack:** TypeScript strict, Vitest, existing `KarmicStore`/`Citta` classes, MCP SDK + zod, Claude Code plugin.

**Spec:** docs/superpowers/specs/2026-08-30-v02-depth-design.md — the binding authority; every constant below (6h gap, weights 0.5, strength mappings, ≤3 seeds/vīthi, priority order) comes from it.

## Global Constraints

- `npm run typecheck`, `npm run lint`, `npm run test:run` green after every task (241 pre-existing tests are the contract; `getState()` additions are additive-only).
- `Being.persistence.test.ts:30` contract: exactly 1 `karmicStream` entry per `act()` — seeds never leak into that array.
- Karma quality is ALWAYS derived from root — no adapter may accept a caller-supplied quality.
- `KarmicStore` is ALWAYS constructed/restored with `enableAutoRipening: false` (no timers, MCP/CLI safety).
- Store seeds planted by Being use `minDelay: 0` and `maxDelay: Number.MAX_SAFE_INTEGER` — eligibility is governed by incarnation windows and conditions, never wall-clock expiry (the store's 5-minute default `maxDelay` would silently exhaust cross-session seeds).
- Randomized ripening is never asserted directly in tests: use `force`, condition-gated assertions, or potency-100 seeds.
- MCP tool count 14 → 16; update README.md, CLAUDE.md, `plugin/commands/buddha.md`, and `scripts/mcp-smoke.sh` (hardcodes `-eq 14`) in the tasks that change the count.
- All docs/comments/commits in English. Conventional commits. No push/publish during tasks.
- Where a step says "transcribe from `<file:line>`", the implementer copies the real field names from that source — inventing names that "look right" is the historical failure mode this repo has already shipped once.
