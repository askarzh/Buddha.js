# v0.5 `dsh-plugin-buddha` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `dsh-plugin-buddha` — a DeepSeek Harness (Cordis) plugin that adds the Poison Arrow circuit breaker, a Being-per-session karma layer, `/sit` `/koan` `/status` `/rebirth` commands, six-realm subagent personas, and the citta-vīthi step model (Layer A; Layer B gated) — with a real-composition test that boots dsh headless against a mock LLM.

**Architecture:** New package dir `dsh/` in the monorepo (ESM, tsup, vitest, **pnpm** — npm cannot resolve dsh's tree on 8 GB machines). Plugin = `apply(ctx, config)` mounting sub-plugins that only use verified Cordis/DSH seams (`ctx.on` waterfalls, `ctx.commands`, `ctx.subagents`, `ctx.systemPrompt`, `ctx.llm`). Buddha.js core (`src/`) is untouched except for public exports the plugin needs.

**Tech Stack:** `@deepseek-ai/cordis@4.0.2` (peer), `@deepseek-ai/dsh@0.1.1-rc.2` (dev, pinned exactly), `@deepseek-ai/schemastery` (`z`-style config schema, as dsh's own plugins use), tsup, vitest, pnpm.

**Spec:** docs/superpowers/specs/2026-08-31-v05-dsh-plugin-design.md (binding; amended after the Antigravity cross-review — five contract corrections, breaker waterfall/streak policy, `spawn` delegation, Layer B go/no-go).

## Global Constraints

- Root suite stays green (`npm run typecheck && npm run lint && npm run test:run`, 339 tests) after every task; `dsh/` has its own `pnpm test` that must be green too.
- `dsh/` depends on Buddha.js ONLY through public exports (`Being`, `REALM_CLASSES`, `Realm`, `PoisonArrow`, `KoanGenerator`, `serializeBeing`/`deserializeBeing` via `Being.toJSON/fromJSON`); if an export is missing, add it to `src/index.ts` in the same task (additive only).
- Every DSH contract used must match the verified table in the spec; the compat test (Task 1) is the tripwire. Never `JSON.stringify` a live Being or Agent into a DSH message.
- Waterfall discipline: every `tools/post-execute` / `agent/pre-step` listener `await next()` first and returns the downstream decision (possibly augmented) — never a fresh object that drops downstream plugins.
- Read-only surfaces (`/status`) never settle a pending rebirth and never persist; mutating paths settle first (v0.3 rule).
- No timers in the plugin except via `ctx.effect` disposers; all listener/registration disposers are owned by the fiber (Cordis handles this — but any `setInterval` is forbidden).
- Docs/comments/commits in English; conventional commits; no push during tasks; plugin content changes bump `dsh/package.json` version.
- Verified names to use verbatim: events `tools/post-execute`, `tools/result`, `agent/pre-step`, `agent/request`, `agent/turn-stopping`, `subagent/start`, `subagent/end`; services `ctx.tools`, `ctx.commands`, `ctx.subagents` (`registerProvider`, `getProvider(name)`, `start(name, request)`), `ctx.systemPrompt.section({name, order, text})`, `ctx.llm.registerAdapter(providers: string[], adapter: LlmAdapter)`, `ctx.agents.setFactory(factory)`; stock plugin ids `agent-loop`, `agent-default-model` (config `{provider, model}`), `llm-deepseek`; stock in-process subagent provider name `spawn`; mutating tool names `write`, `edit`, `str_replace_editor`; message shape `{ id: MessageId, role: 'user', content: [{ type: 'text', text }], source: { kind: 'plugin', plugin: 'dsh-plugin-buddha' } }` (transcribe the `MessageId` minting helper from an installed plugin that emits `kind: 'plugin'` messages — `grep -rn "kind: \"plugin\"" node_modules/.pnpm/@deepseek-ai+dsh-*/node_modules/@deepseek-ai/*/lib/index.js`).

### Task 3: Poison Arrow circuit breaker (`breaker.ts`)

**Files:** Create `dsh/src/breaker.ts`, `dsh/src/messages.ts` (plugin-sourced `UserMessage` builder), `dsh/tests/breaker.test.ts`.

**Interfaces (Produces):**
```ts
export interface StreakKey { agentId: string; tool: string }
export class BreakerState {           // one per agent, created inside agent-scoped effects; disposed with the agent
  recordFailure(tool: string, argsHash: string, stepId: string): number   // returns streak; identical argsHash counts +2; same stepId counts once
  recordSuccess(tool: string): void                                        // resets that tool's streak
  recordMutatingCall(): void                                               // resets ALL streaks (intervening edit)
  streak(tool: string): number
}
export function applyBreaker(ctx: Context, deps: { registry: BeingRegistry; config: Config['breaker'] }): void
```
Listener (waterfall, exact semantics):
```ts
ctx.on('tools/post-execute', async function (exec, result, next) {
  const decision = await next()                                  // ALWAYS delegate first
  if (!config.enabled || !exec.agent) return decision
  if (exec.rootCallId !== exec.callId) return decision           // Code-Mode sub-dispatch: ignore
  const state = stateFor(exec.agent)                             // WeakMap<Agent, BreakerState>, created via exec.agent.ctx.effect
  if (config.mutatingTools.includes(exec.name) && !result.isError) state.recordMutatingCall()
  if (!result.isError) { state.recordSuccess(exec.name); return decision }
  const streak = state.recordFailure(exec.name, hash(exec.arguments), currentStepId(exec.agent))
  if (streak < config.threshold) return decision
  const being = registry.acquire(sessionIdOf(exec.agent)).being
  being.act(`blind retry of ${exec.name}`, Math.min(10, 3 + streak), 'aversion'); registry.save(...)
  const protocol = renderPoisonArrow(exec, result, streak, being)   // PoisonArrow(suffering).step()×4 → text
  const notice = pluginUserMessage(protocol)                         // messages.ts
  if (streak >= 2 * config.threshold && decision.kind === 'accept')
    return { kind: 'block', feedback: [{ type: 'text', text: protocol }], additionalContexts: [...(decision.additionalContexts ?? []), notice] }
  return { ...decision, additionalContexts: [...(decision.additionalContexts ?? []), notice] }
})
```
`currentStepId` comes from a per-agent counter advanced in `agent/pre-step` (Task 4 wires it; until then a monotonically increasing per-call id is acceptable and replaced in Task 4). `hash` = stable JSON stringify + sha1.

- [ ] **Step 1: Failing tests** (pure logic + wiring): (a) three failures on the same tool with different args → third call's decision carries one plugin-sourced `additionalContexts` entry containing "recognize"/"investigate"/"release"/"practice"; (b) identical args reach the threshold on the second failure; (c) a successful `edit` between failures resets the streak; (d) three failures within one `stepId` count once (no trigger); (e) at 2× threshold the decision is `block` with `feedback`; (f) downstream decision is preserved — `next()` returning `{kind:'accept', additionalContexts:[X]}` yields `[X, notice]`, never `[notice]`; (g) sub-dispatch (`rootCallId !== callId`) never counts; (h) `enabled:false` → decision passes through untouched. Tests call the listener via a bare `Context` with `ctx.on` + `ctx.waterfall('tools/post-execute', exec, result, next)` using fake `exec` objects typed against `ToolExecution`.
- [ ] **Step 2:** RED → implement → GREEN. **Commit** `feat(dsh): Poison Arrow circuit breaker on tools/post-execute`
